P4 — CR-H6 defect claim: VERIFIED (reproduced exactly as specified)
--------------------------------------------------------------------
Claim: hmac.compare_digest raises TypeError on a str containing non-ASCII
code points, so a non-ASCII X-JCC-Token is an uncaught exception rather than
a 403.

  compare_digest('中文', '中文')        -> TypeError: comparing strings with
                                           non-ASCII characters is not supported
  compare_digest('中文', 'ascii-token') -> TypeError (same)
  compare_digest('ascii-token','ascii-token') -> True   (ASCII control OK)

Spec option (a) — encode both sides first — removes the exception WITHOUT
changing the verdict:

  compare_digest('中文'.encode(), '中文'.encode())     -> True
  compare_digest('中文'.encode(), 'ascii-token'.encode()) -> False

So (a) satisfies all three acceptance rows: non-ASCII -> refused, correct
ASCII -> still passes, wrong ASCII -> still refused. I intend (a); it deletes
the exception path instead of catching it, and compare_digest on bytes is
still constant-time.
