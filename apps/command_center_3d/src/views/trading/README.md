# Trading Workbench (Paper Trading × Night Researcher)

A set of six expert-mode surfaces for the JEV command center, built on the Paper
Trading API (`/api/v1/trading`) and the Night Researcher six-role pipeline.

All balance / position / risk data is **server-derived** — the browser is never
the authority on those numbers. No real exchange, no real funds.

## Routes (added to `ViewMode` + `NAV_ITEMS`)

| id                | 中文标签   | 说明 |
| ----------------- | ---------- | ---- |
| `market-overview` | 行情总览   | BTC/ETH/ORDI 实时行情、账户资产、策略状态 |
| `trading-desk`    | 交易台     | K 线、订单簿、下单（需人工确认） |
| `agent-center`    | 智能体中心 | 六角色运行记录（SPOTTER/PRIOR/EDGE/KELLY/TAKER/CLOSER） |
| `risk-management` | 风险管理   | 持仓、敞口、最大回撤、风险拒绝 |
| `strategy-research` | 策略研究 | 回测/样本外/收益/版本表 |
| `trading-audit`   | 交易审计   | 订单、成交、账本、事件回放 |

All six are `visibility: "advanced"`, group `Work`, so they appear in Expert Mode
only. They are lazy-imported in `src/App.tsx` (mirroring the 3D-view pattern) so
they never enter the initial bundle.

## API contract (mirrored in `services/types.ts`)

Base: `/api/v1/trading`. Methods (see `services/paperApi.ts`):

- `getMarketSnapshot({ symbols, interval })` → `MarketSnapshot[]`
- `getOrderBook({ venue, symbol })` → `OrderBook`
- `createResearchRun({ providerId, symbols, snapshotId, strategyVersion, modelOverride })` → `ResearchRun`
- `getResearchRun(runId)` → `ResearchRun`
- `listStrategies()` → `Strategy[]`
- `getPaperAccount()` → `PaperAccount`
- `createPaperOrder({ symbol, side, type, quantity, limitPrice?, confirmationId, researchRunId? })` → `PaperOrder`
- `cancelPaperOrder(orderId)` → `{ ok, orderId }`
- `subscribeEvents({ after? })` → `LedgerEvent[]`

## Mock flag

`services/paperApi.ts` exports `USE_MOCK` (default `true`). While `true`, every
method resolves from typed fake data in `services/mockData.ts` — no network, no
backend required. The shapes match the contract exactly, so flipping the flag
requires no page changes.

### Switching to the real backend

1. Merge/deploy the backend at `/api/v1/trading`.
2. Set `USE_MOCK = false` in `services/paperApi.ts`.
3. The real client reuses the existing transport
   (`authorizedFetch` / `openFetch` from `src/lib/authorizedFetch.ts`) and binds
   the control token threaded down from `App`. No second provider/API-key system
   is created — the existing Provider Center remains the only place providers are
   configured.

## Human-confirmation rule

`createPaperOrder` requires a `confirmationId` generated by an explicit operator
confirmation in the Trading Desk. `validateOrderProposal` (in `lib/finance.ts`)
and the server both reject proposals without it — **TAKER proposals MUST NOT
bypass this**. The confirmation checkbox in `TradingDesk.tsx` is the only thing
that injects the id.

## K-line rendering

`components/CandlestickChart.tsx` prefers `lightweight-charts` (declared in
`package.json` `devDependencies`), loaded via a **guarded dynamic import** so the
offline build type-checks against `lightweight-charts.d.ts`. When the package is
absent (this environment) or canvas is unavailable, it falls back to a pure SVG
candlestick renderer. No `npm install` of `lightweight-charts` is performed here.
